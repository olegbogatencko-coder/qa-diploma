# План автоматизации тестирования

## 1. Перечень автоматизируемых сценариев
**Позитивные сценарии (Happy Path):**
1. Успешная покупка тура по дебетовой карте (карта `APPROVED`). Проверка появления сообщения об успехе и записи в БД.
2. Успешная покупка тура в кредит (карта `APPROVED`). Проверка появления сообщения об успехе и записи в БД.

**Негативные сценарии:**
3. Отказ в оплате по дебетовой карте (карта `DECLINED`). Проверка появления сообщения об ошибке и записи в БД со статусом отказа.
4. Отказ в выдаче кредита (карта `DECLINED`). Проверка появления сообщения об ошибке и записи в БД.
5. Отправка полностью пустой формы оплаты. Проверка появления сообщений об обязательности заполнения всех полей.
6. Отправка формы с невалидным номером карты (например, слишком короткий номер или текст).
7. Отправка формы с истекшим сроком действия карты.
8. Отправка формы с невалидным CVC/CVV кодом (например, 2 цифры вместо 3).

**Проверка работы с БД:**
9. После каждого сценария проверять таблицу `payment_entity` (и `credit_request_entity` для кредитов). Убедиться, что статус (`APPROVED`/`DECLINED`) записан верно, способ оплаты корректен, и **нет сохраненных данных карты** (номер, владелец, CVC не должны сохраняться в БД).

## 2. Перечень используемых инструментов с обоснованием выбора
* **Java 11 (или 17)** — основной язык программирования.
* **Gradle** — система сборки (уже настроена в проекте).
* **Selenide (или Selenium WebDriver)** — для UI-тестов. Selenide выбран за удобство, неявные ожидания и меньшее количество boilerplate-кода.
* **JUnit 5** — фреймворк для написания тестов.
* **Allure** — для генерации наглядных отчетов о прогоне тестов.
* **JDBC (или библиотека DBUtils)** — для подключения к СУБД (MySQL/PostgreSQL) и выполнения SQL-запросов в тестах.
* **Docker и docker-compose** — для развертывания баз данных (MySQL, PostgreSQL) и эмулятора банковских сервисов.

## 3. Перечень и описание возможных рисков при автоматизации
* **Нестабильность UI (Flaky tests):** Из-за задержек рендеринга страницы тесты могут падать. *Решение: использование неявных ожиданий Selenide.*
* **Проблемы с окружением Docker:** Базы данных могут долго запускаться или занимать порты. *Решение: использование healthcheck в docker-compose или пауза перед запуском тестов.*
* **Изменение структуры БД:** Приложение может обновляться, и названия таблиц/колонок могут измениться. *Решение: вынос SQL-запросов в отдельные константы.*

## 4. Интервальная оценка с учётом рисков (в часах)
* Развертывание и настройка окружения: 2-3 часа.
* Написание Page Object'ов: 4-6 часов.
* Написание автотестов (UI и БД): 8-12 часов.
* Настройка Allure и написание отчета: 2-3 часа.
* **Итого:** ~20-25 часов.

## 5. План сдачи работ
* **Написание автотестов:** 3-4 дня с момента утверждения плана.
* **Прогон тестов и исправление багов:** 1 день.
* **Подготовка отчетности (Report.md, Summary.md):** 1 день.
* **Финальная сдача:** через 5-6 дней.
